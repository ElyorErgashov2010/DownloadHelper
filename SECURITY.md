# Security Policy / Xavfsizlik siyosati

## Supported Versions / Qo'llab-quvvatlanadigan versiyalar

| Version | Supported / Holati |
| --- | --- |
| `main` branch | :white_check_mark: Current development / Joriy rivojlanish |
| Latest `v1.4.x` release | :white_check_mark: Supported / Qo'llab-quvvatlanadi |
| Older releases | :x: Not supported / Qo'llab-quvvatlanmaydi |

## Reporting a Vulnerability / Xavfsizlik muammosini xabar qilish

**Please do not disclose a potential security vulnerability in a public Issue.**

1. Use the repository's **Security** tab and select **Report a vulnerability**
   when private vulnerability reporting is available.
2. Include a clear description, affected version, reproducible steps, potential
   impact, and any safe proof of concept.
3. Do not include passwords, S3 credentials, access tokens, private media URLs,
   decryption keys, or personal data in a report.

The maintainer will review a report in good faith, assess the impact, and
coordinate a fix or disclosure where appropriate. Please allow reasonable time
for investigation before sharing details publicly.

---

**Ehtimoliy xavfsizlik muammosini ochiq GitHub Issue orqali yozmang.**

1. Agar mavjud bo'lsa, repository'dagi **Security** varag'idan **Report a
   vulnerability** tugmasini bosing.
2. Muammo tavsifi, ta'sir qilgan versiya, qayta takrorlash qadamlari va
   ehtimoliy ta'sirini yozing.
3. Parol, S3 access key/secret key, token, shaxsiy media URL, decryption key
   yoki shaxsiy ma'lumotlarni xabarga qo'shmang.

Maintainer xabarni vijdonan ko'rib chiqadi, ta'sirini baholaydi va kerak bo'lsa
muammoni tuzatish yoki oshkor qilish jarayonini muvofiqlashtiradi. Tafsilotlarni
ochiq e'lon qilishdan oldin tekshiruv uchun yetarli vaqt bering.
